# 스킬 카탈로그 & 에이전트 지시법

**스킬**은 이 프로젝트에 저장된 에이전트 작업 절차서다. 실체는 `.claude/skills/<이름>/SKILL.md` 마크다운이다.

- **Claude Code** — `/이름` 으로 호출
- **다른 에이전트** — "`.claude/skills/<이름>/SKILL.md` 를 읽고 그대로 해라" 로 지시 ([other-agents.md](other-agents.md) §5)

**"자동" 표시가 있는 스킬은 에이전트가 사람 지시 없이 알아서 호출해도 되는 것들이다.** 나머지는 사람이 부른다.

---

## 1. 한눈에 보기

| 스킬 | 한 줄 | 언제 | 자동 |
|---|---|---|---|
| [`/setup`](#setup) | 개발 환경 부트스트랩 | 첫 클론 / 컴퓨터 옮겼을 때 | — |
| [`/task-start`](#task-start) | 작업 착수 브리핑 — 범위·규칙·테스트 계획 확정 | **모든 작업 시작** | ✓ |
| [`/task-done`](#task-done) | 작업 마무리 — 검증·커밋 게이트·지식 승격 | **모든 작업 완료** | ✓ |
| [`/design`](#design) | 기획을 단계별 작업서로 분해 | 새 기획을 받았을 때 | — |
| [`/run`](#run) | 빌드 / 에디터 실행 / Bridge 배치 | 실행·검증이 필요할 때 | ✓ |
| [`/qa`](#qa) | 기준 대비 합격·불합격 판정 | 릴리즈 전, 위험한 변경 후 | — |
| [`/debug`](#debug) | 버그 원인 추적·재현 | 버그·예외를 만났을 때 | — |
| [`/make-asset`](#make-asset) | 프리팹·파티클·아이콘 즉석 제작 | 참조할 에셋이 없을 때 | ✓ |
| [`/synth`](#synth) | 8비트풍 효과음·BGM 생성 | AudioClip 이 비어 있을 때 | ✓ |
| [`/lsp-setup`](#lsp-setup) | C# 언어 서버(OmniSharp) 연결 | `.cs` LSP 미연결 시 | ✓ |
| [`/self-update`](#self-update) | 세션에서 얻은 지식을 지침으로 승격 | 새 패턴·반복 실수 발견 시 | — |

## 2. 기본 작업 흐름

일상 작업은 이 순서로 흐른다. 양 끝의 두 스킬은 에이전트가 알아서 부른다.

```
/task-start  →  (TDD: 실패 테스트 → 구현 → 리팩터)  →  /task-done
     ↑                        ↓                            ↓
  범위·규칙 확정      막히면 /debug, 실행은 /run      커밋 게이트 통과
```

기획 단위로 크게 시작할 때는 앞에 `/design` 을 붙인다.

```
/design  →  단계별 작업서 생성  →  각 단계마다 /task-start ~ /task-done
```

## 3. 스킬별 상세

### `/setup`

환경 세팅. OS 감지 → `uv` 확인·설치 → `.mcp.json` 확인 → Unity Editor 확인 → Bridge MCP 연결 테스트까지 한 번에.

사람이 할 일은 `/setup` 입력과 권한 승인뿐이다. 이미 세팅돼 있으면 검사만 하고 끝난다. 자세히는 [claude-code.md](claude-code.md) §2.

---

### `/task-start`

**작업 전에 범위를 먼저 못 박는 브리핑.** 파일을 열기 전에 돌린다.

에이전트가 선언하는 것:
- `.claude/INDEX.md` 로 **선별 로드** — 이번 작업에 필요한 지침만 (전부 읽으면 토큰 낭비)
- 이번 작업에 걸리는 `RULE-NN`
- 건드릴 어셈블리·파일 / **건드리지 않을** 파일
- **테스트 계획** — 어느 EditMode 테스트를 먼저 실패시킬 것인가
- 현재 브랜치가 `feat/*` 인지 (아니면 브랜치 생성 제안)
- `CLAUDE.md` §7 사람 승인이 필요한 항목이 있는지

> 브리핑이 부실하면 그 자체가 경고 신호다. "무엇을 안 건드릴지"를 말하지 못하면 범위가 안 잡힌 것이다.

---

### `/task-done`

**마무리 루틴.** 코드만 고치고 세션을 끝내는 건 반쪽짜리다.

- 변경 요약 + 의도하지 않은 변경 확인
- 자체 검증 — 이벤트 해제 쌍, `CancellationToken`, 밸런스 하드코딩 여부, 로직/`MonoBehaviour` 분리, 어셈블리 의존 방향, `SushiPool` 경유
- **커밋 전 체크리스트** (`CLAUDE.md` §8) — 포맷/린트, 컴파일, **테스트 전량**, **에셋 유출 점검**, 신규 로직의 테스트 동반
- 새로 알게 된 이 프로젝트만의 지식을 `.claude/domain/` 으로 승격 제안

> **에셋 유출 점검**은 실수하기 쉬운 지점이다. 원본 스프라이트·음원이 의도치 않게 스테이징됐는지 보고, 커밋 여부는 사람이 정한다 (`CLAUDE.md` §9).

---

### `/design`

기획(자연어 또는 링크)을 받아 `design/{슬러그}/` 에 **단계별 작업서**를 만든다. 각 단계는 다음 에이전트가 그대로 실행할 수 있는 독립 프롬프트다.

이 프로젝트의 기본 분해 순서:

```
1) SO 스키마 정의 (Runtime.Data)
2) EditMode 실패 테스트 작성 (Tests.EditMode)
3) 순수 로직 구현 (Runtime)
4) View/Presenter 연결 (Presentation)
5) 씬·프리팹 조립
```

한 단계 = 한 어셈블리가 원칙이다. 여러 어셈블리를 한 번에 건드리는 단계는 쪼갠다. 코드는 쓰지 않고 계획만 만든다.

---

### `/run`

| 인자 | 동작 |
|---|---|
| `webgl` | **실제 배포 타깃.** 릴리즈 검증은 반드시 이것으로 |
| (없음) | 현재 OS 로 빠른 로컬 빌드 |
| `editor` | Unity Editor GUI 실행 |
| `bridge` | 큐에 쌓인 Bridge 커맨드를 헤드리스로 일괄 실행 |

빌드 산출물은 **저장소 밖** `builds/` 에 떨어진다. 로그 전문을 대화창에 쏟지 않고 원인 라인만 요약해 보고하게 돼 있다.

---

### `/qa`

**기준 대비 합격·불합격을 에이전트가 판정한다.** "플레이해 보고 이상하면 말씀해 주세요" 는 금지다.

절차: 합격 기준을 문서 링크로 고정 → LSP/Grep 정적 평가 → 필요한 것만 Bridge 로 런타임 확인 → **기준별 Pass/Fail + 증거(파일:라인)** 보고.

검사 항목에는 `RULES.md` 준수, 밸런스 하드코딩, 로직/`MonoBehaviour` 분리, 어셈블리 의존 방향, 테스트 동반, **타겟팅 오용**, **손님이 구경하지 않는지** 등이 포함된다.

> `/qa` 는 EditMode 테스트 스위트를 **대체하지 않는다.** 테스트로 못 잡는 것(규칙 준수, 기획 조항 커버리지, 런타임 상태 전이, 성능 예산)을 본다.
>
> **밸런스 수치 자체는 QA 대상이 아니다.** "손님이 너무 빨리 배부르다"는 버그가 아니라 기획 판단이다. 에이전트는 "그 값이 어느 SO 필드에서 온다"까지만 보고한다.

---

### `/debug`

**에이전트가 직접 원인을 짚는다.** "브레이크포인트 걸어 주세요" 는 금지다.

정적 평가(LSP 로 호출 그래프 추적) → 범위를 좁힌 뒤 Bridge 로 재현·값 확인 → **재현 테스트를 먼저 쓰고** 고친다(TDD). 방법론은 Adragna 디버깅 10원칙(`.claude/knowledge/debugging/`)을 따른다.

증상별 1순위 툴이 표로 정리돼 있다. 예를 들어 **"손님이 눈앞 초밥을 안 집고 구경한다"** 의 1순위 용의자는 **타겟팅을 집기 게이트로 오용한 코드**다.

---

### `/make-asset`

참조할 에셋이 없을 때 즉석 제작한다. UGUI 프리팹 / 파티클 / 프리미티브 placeholder 모델 / **SVG 를 직접 그려 PNG 로 래스터화한 아이콘**. 외부 그래픽 도구가 필요 없다.

씬을 조립하다 프리팹이 없으면 에이전트가 알아서 부르고 한 줄로 고지한다. 최종 아트는 **일본풍 2D 픽셀 아트**이며, SVG placeholder 는 임시일 뿐 사람이 그린 원본을 덮어쓰지 않는다.

---

### `/synth`

Python 표준 라이브러리만으로 8비트풍 WAV 를 만든다 (피아노·패드·리드·베이스·앰비언트 프리셋 + ADSR·비브라토·디튠·bitcrush).

"초밥 집기", "포화", "매출 획득", "스테이지 클리어" 같은 피드백에 `AudioClip` 이 비어 있으면 에이전트가 임시 사운드를 만들어 둔다. 톤은 **경쾌한 일본풍 + 맛깔난 음식 효과음**.

---

### `/lsp-setup`

`No LSP server available for file type: .cs` 가 뜨면 OmniSharp 를 자동 설치·연결한다. `/debug`·`/qa` 가 LSP 미연결을 감지하면 알아서 부른다.

---

### `/self-update`

세션에서 얻은 지식을 5개 계층 중 맞는 곳에 승격 제안한다.

```
시스템이 실제로 망가지는 규칙?        → RULES.md
어느 Unity/C# 프로젝트에나 적용?      → .claude/knowledge/
이 프로젝트만의 기획·시스템 관계?     → .claude/domain/
특정 경로에서만 필요한 규칙?          → .claude/rules/
그 외 프로젝트 개요                   → CLAUDE.md (+ AGENTS.md 동시 갱신)
```

**직접 커밋하지 않고 diff 로 제안한 뒤 승인을 기다린다.**

## 4. 에이전트에게 지시하는 법

### 잘 작동하는 패턴

**(1) 결과가 아니라 "무엇을 만족해야 하는지"를 준다**

```
손님이 초밥을 집는 로직을 만들어라.
- 집기 조건은 범위·포화도·상태만 본다. 가격은 조건에 넣지 마라 (CLAUDE.md §1.1-3a)
- 같은 초밥에 후보가 둘 이상이면 타겟팅 우선순위로 정하고, 동률은 임의로
- 수치는 전부 CustomerData 필드에서 읽는다
- EditMode 테스트를 먼저 쓴다
```

**(2) 애매하면 `/design` 부터**

여러 어셈블리에 걸치는 기획이면 바로 구현시키지 말고 `/design` 으로 쪼갠 뒤, 단계별로 실행한다.

**(3) "안 건드릴 것"을 명시한다**

```
StageConfig 는 이번 작업에서 수정하지 마라. 읽기만 해라.
```

**(4) 검증 방법을 같이 준다**

```
끝나면 /run bridge 로 컴파일 확인하고 EditMode 전량 돌려서 결과를 보고해라.
```

### 피해야 할 패턴

| 이렇게 말하면 | 문제 | 대신 |
|---|---|---|
| "손님이 좀 이상해, 고쳐줘" | 기준이 없어 감으로 고친다 | 기대 동작과 실제 동작을 구체적으로 |
| "밸런스 좀 맞춰줘" | §7 위반 — 기획 판단 영역 | 사람이 값을 정하고, 에이전트에겐 "어느 SO 필드에서 오는지 찾아라" |
| "테스트는 나중에" | 커밋 게이트 위반 | TDD 가 기본값. 로직과 테스트는 같은 커밋 |
| "머지해줘" | §7 위반 | 에이전트에겐 명령만 제시하게 하고 사람이 실행 |
| "빨리 대충" | 지침을 건너뛰게 만든다 | 범위를 줄여라. 품질 기준이 아니라 |

### 에이전트를 멈춰야 하는 신호

- `/task-start` 없이 바로 파일을 고치기 시작한다
- 밸런스 수치를 코드 상수로 박는다
- 타겟팅을 집기 조건으로 쓴다 (`if (price < min) return false`)
- 테스트 없이 새 로직을 만든다
- `git merge` / 브랜치 삭제 / `ProjectSettings` 수정을 **승인 없이 실행**한다
- 새 `.asmdef` 나 새 패키지를 임의로 추가한다
- 사용자에게 "플레이해 보고 알려 주세요" 라고 미룬다

이런 게 보이면 지침이 로드되지 않은 것이다. **`.claude/INDEX.md` 부터 다시 읽으라고 지시**하고 작업을 되돌린다.

## 5. 스킬을 고치거나 추가할 때

- 스킬 파일은 `.claude/skills/<이름>/SKILL.md`, frontmatter 의 `name` 이 호출 이름이다
- **새 스킬·지침 파일을 추가하면 `.claude/INDEX.md` 도 같이 갱신한다.** 인덱스에 없으면 다음 세션의 선별 로드에서 발견되지 않아 사실상 없는 파일이 된다
- 스킬 자체의 변경은 아키텍트 영역이다 (`/self-update` 는 제안까지만)
