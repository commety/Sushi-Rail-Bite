# M6.5 — 인스테이지 UX 확장 (신규 기능)

> **출처**: M6 step-13 완료 후 WebGL 실플레이 리포트 (2026-08-09).
> 리포트는 **오류 의심**과 **신규 기능**이 섞여 있었다. 오류 의심은
> `feat/m6-main-screen-and-flow` 에서 그대로 고치고, **여기 남은 넷은 새 기능**이라
> 마일스톤을 갈라 둔다.

## 왜 M6 에 넣지 않았나

넷 모두 **지금 동작이 틀린 것이 아니라 없는 것**이다. 버그 수정과 한 브랜치에 섞으면
리뷰가 "고쳐진 것"과 "새로 생긴 것"을 구분하지 못하고, 롤백 단위(`CLAUDE.md` §6.3)도
뭉개진다. 특히 F1 은 **밸런스 SO 스키마를 바꾸므로** §7 승인이 별도로 필요하다.

## F1. 손님이 자리를 하나 이상 차지한다 (인구수)

### 요구

> 먹보는 손님 수 2를 차지한다.

지금 배치 한도(`StageConfig.MaxPlacedCustomers`)는 **머릿수**를 센다
(`CustomerPlacementService.PlacedCount = _bySlot.Count`). 먹보가 둘을 차지하려면
한도가 세는 단위가 **머릿수에서 인구수로** 바뀌어야 한다.

### 이 요구가 건드리는 것

| 영역 | 무엇 |
|---|---|
| `Runtime.Data` | `CustomerData` 에 인구수 필드 신설 (`[Min(1)]`, 기본 1) |
| `Runtime` | `CustomerPlacementService.PlacedCount` 의 의미 변경 — 합계로 |
| `Presentation` | `StageHudView` 의 `손님 n/m` 이 인구수 기준이 된다 |
| `.asset` (§7) | 손님 3종 + Placeholder 의 값 결정 — **사람 승인** |
| 밸런스 | 스테이지 1~3 의 `MaxPlacedCustomers` 재검토. 먹보가 2를 먹으면 실질 한도가 준다 |

### 결정이 필요한 것

- **필드 이름.** `RecruitCost` 와 나란히 놓이는 자리다. `Population`? `SeatCost`?
  `CLAUDE.md` §2 용어 사전에 등재해야 한다 — 이름이 정해지기 전에 코드에 넣지 않는다.
- **자리(`TableSlot`)와의 관계.** 인구수 2인 손님이 **자리도 둘** 차지하는가, 아니면
  자리는 하나인데 한도만 둘을 먹는가. 전자면 `_bySlot` 구조와 드롭 판정이 통째로 바뀌고,
  후자면 한도 계산만 바뀐다. **후자를 제안한다** — 요구가 "손님 수"라고만 적었고,
  자리 점유까지 늘리면 `SlotPicker`·드래그 판정·씬 자리 배치가 함께 딸려 온다.
- **소식가는 0.5인가.** 정수로 두면 소식가는 1이다. 분수를 도입하면 한도 표시가
  `2.5/4` 가 되어 읽기 나빠진다 — **정수 유지를 제안**한다.

### 완료 판정

- [ ] 인구수 2인 손님을 앉히면 `손님 n/m` 이 2 늘어난다
- [ ] 남은 인구수보다 큰 손님은 잔액이 충분해도 카드가 흐려진다
- [ ] `CustomerPlacementServiceTests` 에 "한도가 머릿수가 아니라 합계다" 가 있다

## F2. 소화 중 남은 시간을 배지에 함께 표시

### 요구

> 손님 비활성화(소화) 상태일 때 남은 시간을 바로 표시하는 것이 좋다.

지금 `DigestingBadgeView` 는 **켜고 끄기만** 한다 (16×16 아이콘 하나). 남은 시간은
`CustomerRuntimeState` 가 이미 들고 있으므로 **새 계산은 없고 표시만 는다.**

### 걸리는 제약

- **폰트가 12px 이다.** 배지가 16×16 이라 그 안에 숫자를 넣으면 한 자리가 한계다.
  `DigestingBadgeView` 의 클래스 주석이 이미 이 이유로 «글자가 아니라 아이콘» 을 골랐다 —
  **배지를 키우거나 옆에 붙이는 것 중 하나를 정해야 한다.**
- **매 프레임 문자열을 만들지 않는다** (§4.3, WebGL). 초 단위로 잘라 바뀐 프레임에만 쓴다 —
  `StageHudView.RefreshTime` 과 같은 형태다.
- 한글 서브셋에 숫자가 이미 있는지 확인해야 한다 (`charset-ko.txt`).

### 결정이 필요한 것

- 원형 게이지(시계 방향으로 줄어드는 링)인가 숫자인가. **게이지면 폰트 제약이 사라진다.**

### 완료 판정

- [ ] 소화 중인 손님 위에 남은 시간이 보이고, 0 에 닿으면 배지가 사라진다
- [ ] 값이 바뀐 프레임에만 갱신된다 (초 단위)

## F3. 배치된 손님을 클릭하면 정보 창이 뜬다

### 요구

> 손님 유형 · 손님 스탯 · `현재 포화도/최대 포화도` · 현재 상태 ·
> 소화중인 경우 다 소화될 때까지 남은 시간.

### 이것은 F4·«창 하나만» 규칙과 맞물린다

버그 수정 쪽에서 **창 우선순위**를 확정한다:

```
메뉴 > 덱빌딩 > 보상선택 > 인 게임 정보 창
```

**F3 이 그 최하위 창이다.** 따라서 우선순위 조정자(코드)는 버그 수정에서 이미 만들어지고,
F3 은 거기에 항목 하나를 등록하는 형태가 된다 — **버그 수정이 먼저 들어가야 한다.**

### 이 요구가 건드리는 것

| 영역 | 무엇 |
|---|---|
| `Presentation` | `CustomerInspectorPresenter` (순수 C#) + `CustomerInspectorView` |
| `Presentation` | `CustomerView` 에 클릭 입력 — **판정은 넣지 않는다.** 좌표만 넘긴다 |
| 씬 | 패널 하나 + 라벨들 |

### 결정이 필요한 것

- **클릭 히트박스.** 손님이 월드 스페이스 `SpriteRenderer` 라 uGUI 레이캐스트가 닿지 않는다.
  `SlotPicker` 와 같은 «좌표 → 가장 가까운 자리» 방식을 재사용할 수 있다 —
  **콜라이더를 새로 도입하지 않는 편을 제안**한다 (RULE-04 물리 규칙이 따라오지 않는다).
- **드래그 배치와 충돌하지 않는가.** 카드를 자리에 떨어뜨리는 동작과 자리를 클릭하는
  동작이 같은 좌표에서 일어난다. 드롭이 아닌 «클릭» 만 정보 창을 여는 판정이 필요하다.
- **일시정지하는가.** M6 D8 이 «덱 보기는 일시정지하지 않는다» 를 이미 정했다 —
  정보 조회는 멈추지 않는다는 같은 판단을 따르는 것을 제안한다.

### 완료 판정

- [ ] 앉아 있는 손님을 클릭하면 유형·대역·범위·먹는 시간·소화 시간·영입 비용이 보인다
- [ ] `현재/최대` 포화도와 현재 상태가 실시간으로 갱신된다
- [ ] 우선순위가 더 높은 창이 떠 있으면 열리지 않는다

## F4. 카드 128×192px 규격과 접히는 손패

### 요구 — 카드 레이아웃

> - 최상단 우측에 영입 비용 표시 (동전 모양 안에 숫자, 16px 높이)
> - 영입 비용 레이아웃 아래 **최소 12px** 높이의 카드 이름 필드
> - 이름 필드 아래 **최소 8px 패딩**을 포함한 32×32px 이미지 공간 (총 40×40px)
> - 이미지 아래에 스탯을 행 별로

```
┌──────────────── 128 ────────────────┐
│                        ╭───╮        │ ← 영입 비용 (동전 16px)
│                        │ 60│        │
│                        ╰───╯        │
├─────────────────────────────────────┤
│              먹  보                  │ ← 이름 (최소 12px)
├─────────────────────────────────────┤
│              ┌────┐                 │
│              │32×32│                │ ← 아이콘 (패딩 8px, 총 40×40)
│              └────┘                 │
├─────────────────────────────────────┤
│  범위      6                        │
│  대역   100~300                     │ ← 스탯 (행 단위)      192
│  포화도    8                        │
│  소화      4초                      │
└─────────────────────────────────────┘
```

### 요구 — 접히는 손패 (collapsible hand)

> 스테이지에서 카드가 너무 크면 마우스를 가져다대었을 때만 위로 나오는 pop-up 방식.

카드가 128×192 가 되면 **인스테이지 손패가 화면을 먹는다.** 평소에는 아래로 내려
일부만 보이고, 호버하면 올라온다.

### 걸리는 제약

- **`CardView` 는 틀 하나다** (M6 D3). 덱빌딩·보상·손패가 같은 프리팹을 쓰므로
  **크기를 바꾸면 세 화면이 동시에 바뀐다.** 그것이 요구의 의도이기도 하다
  («덱빌딩 카드처럼 레이아웃이 구성된다»).
- **호버는 터치에 없다.** 배포 타깃이 웹이라 모바일 브라우저가 사정권이면
  탭으로도 열리는 경로가 필요하다.
- 스탯 행이 늘면 **한글 서브셋 재굽기**가 따라온다 (M6 §7-6, 사람이 돌린다).
- `_dropRadius`·카드 홈 좌표(`CustomerCardDrag._home`)가 손패 애니메이션과 맞물린다 —
  카드가 올라온 상태에서 끌면 `_home` 이 어느 쪽인지 정해야 한다.

### 결정이 필요한 것

- **아이콘이 32×32 인데 카드는 128 폭이다.** 4배 확대해 채우는가, 원본 크기로 두는가.
  픽셀 아트라 **정수배 확대만** 허용된다 (M5 임포트 규칙).
- 스탯을 몇 줄까지 보여 주는가. 손님과 초밥이 가진 필드 수가 다르다.

### 완료 판정

- [ ] 카드가 128×192 이고 위 4구획이 규격대로 배치된다
- [ ] 덱빌딩·보상·손패 세 화면이 같은 프리팹을 쓴다
- [ ] 인스테이지 손패가 평소에 접혀 있고 호버(또는 탭)로 올라온다

## 선행 조건

**버그 수정이 먼저 들어가야 한다.** 두 가지가 물려 있다:

1. **창 우선순위 조정자** — F3 이 그 최하위 항목으로 등록된다
2. **손패 갱신 경로** — 지금 잔액이 늘어도 카드가 다시 평가되지 않는 버그가 있는데,
   F1 이 한도 계산을 바꾸면 같은 자리를 두 번 고치게 된다
