## M5 — UI/UX·아트·사운드 (원본 5차)

배경, 초밥 라인, 초밥·손님 디자인, UI, BGM, 효과음, VFX.

**애셋 단계는 워크트리로 병렬화할 수 없다.** (M5 진행 중 정정)

`Assets/Art` 와 `Assets/Audio` 는 워크트리에서 **심링크**이고(`scripts/ensure-worktree-setup.sh` 의 `SYMLINK_ASSET_DIRS`), M5 결과물 대부분이 그 폴더로 간다. 워크트리에서 만들면 파일이 메인 프로젝트에 생기고 워크트리 git 이 보지 못한다 ([`parallel-work.md`](../../.claude/rules/parallel-work.md) §2).

| 단계 | 워크트리 |
|---|---|
| 스프라이트·오디오·폰트 | **금지** — 메인 프로젝트에서만 |
| 씬 편집 | **금지** — 한 번에 한 워크트리 (§3) |
| 순수 코드 | 가능하지만 이득이 적다 |

지금 알아둘 것:

- **아트 톤** — 일본풍 2D 픽셀 아트, 캐주얼·개그 (README). `/make-asset` 의 SVG placeholder 는 임시일 뿐 사람이 그린 원본을 덮지 않는다
- **픽셀 아트 임포트 설정** — Filter Mode `Point`, Mip Maps 끄기, 압축 신중히. 블록 압축은 픽셀 아트에서 색이 뭉개진다
- **Sprite Atlas 는 이 게임에서 특히 중요하다** — 벨트 위에 여러 종류의 초밥이 동시에 돈다. 묶지 않으면 종류 수만큼 드로우콜이 늘어난다
- **원본 에셋 보호** — 스프라이트·음원 커밋과 외부 업로드는 사람 확인 사항 (`CLAUDE.md` §9)
- **효과음 겹침** — 원본이 이미 지적한 문제. 동시 재생 수 제한·쿨다운·볼륨 덕킹을 설계에 넣는다. `/synth` 로 placeholder 를 먼저 깔고 감을 잡을 수 있다

## M6 — 메인 화면·스테이지 진입 (원본 6차)

메인 화면, 백과사전, 튜토리얼, 설정, 진입 전 손님 고르기·덱빌딩.

지금 알아둘 것:

- **덱빌딩 화면은 MVP 패턴 필수** (`CLAUDE.md` §3.6). `Presenter` 는 순수 C# 이라 EditMode 테스트 대상이다. 여기가 UI 로직 테스트의 주 무대
- **씬 전환 구조**를 여기서 정하게 된다 — 메인 ↔ 덱빌딩 ↔ 스테이지. M3 의 `RunState` 가 씬을 넘어 유지돼야 하므로 Q1(저장/영속)의 답이 여기서도 쓰인다
- 설정은 헤더 고정 (원본 명시)

## M7 — 전체 플로우 검증 (원본 7차)

지금 알아둘 것:

- 이건 `/qa` 스킬이 담당하는 구간이다. **사람이 플레이해서 감으로 보고하는 방식이 아니라**, 기준을 문서로 박고 에이전트가 정적 평가 + Bridge 런타임 확인으로 Pass/Fail 을 낸다
- 검증 기준의 1차 출처는 `CLAUDE.md` §1.1 코어 루프와 각 `M*.md` 의 완료 판정이다. **플랜 문서를 그대로 QA 기준으로 재사용한다**

## M8 — 배포 (원본 8차)

**M0 에서 이미 WebGL 빌드가 통과하고 있어야 한다** ([README §3-(3)](README.md#3-원본-대비-변경한-것--반드시-확인-필요)). 그래서 M8 의 범위는 "처음 빌드해 보기" 가 아니라:

- 실제 호스팅 환경 배포
- **브라우저 호환성 확인** — 되는 것과 안 되는 것을 명시 (원본 요구)
- 초기 로드 크기·로딩 시간 측정. 웹 데모는 이게 이탈률을 좌우한다

지금 알아둘 것:

- WebGL 은 **싱글 스레드** — `Task.Run` 류 병렬화가 동작하지 않는다. M1~M4 에서 스레드를 쓰지 않도록 주의
- **IL2CPP Managed Code Stripping** — 리플렉션·`JsonUtility` 를 쓰면 `link.xml`/`[Preserve]` 가 필요할 수 있다. Q1 에서 저장 기능을 넣기로 하면 직렬화 경로가 여기 걸린다
- 텍스처 압축은 **DXT** 가 데스크톱 브라우저 표준

상세: [`unity-webgl-performance.md`](../../.claude/knowledge/unity-webgl-performance.md) §0

## M9 — QA·밸런싱 (원본 9차)

지금 알아둘 것:

- **밸런싱은 에이전트의 판단 영역이 아니다** (`CLAUDE.md` §7). 에이전트는 "이 값이 어느 SO 필드에서 온다"까지 보고하고, 값 변경은 사람이 한다
- 밸런싱이 가능하려면 **모든 수치가 SO 에 있어야** 한다. M2~M4 에서 하드코딩이 하나라도 새면 여기서 비용을 치른다
- **M3 이후로 조금씩 돌린다.** 마지막에 몰면 늦다
- 값을 바꾼 이유는 `.claude/domain/` 에 남긴다. `.asset` 파일은 이유를 기록하지 못한다

## 번외 (원본 — 선택사항)

시간이 남을 때만. **3스테이지 데모가 최종 목표**이고 아래는 전부 그 다음이다.

- 보스전, 방해물·방해꾼
- 주요 캐릭터를 손님으로 추가
- 테이블 위치 변경·추가

> 방해 요소는 코어 루프의 전제(§1.1-3a)를 건드릴 수 있다. 추가하려면 규칙 재확인부터.
