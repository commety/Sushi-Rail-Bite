# M3 — 스테이지 클리어와 로그라이트 (원본 3차)

> 원본 목표: *"스테이지 목표를 달성하면 클리어한다 / 스테이지 종료 시 보상(초밥 카드 추가 또는 손님 영입)을 선택할 수 있다 / 초밥은 시너지를 가질 수 있다(선택사항)"*

> ⚠️ **시너지는 선택사항으로 격하됐다** (기획 갱신). 클리어·보상이 먼저다. 시너지는 그 뒤에 여유가 있으면 붙인다.

## 목표

한 판이 **끝나는** 게임이 된다. 목표 매출·제한 시간·클리어 판정이 생기고, 클리어 후 보상을 골라 덱이 자란다.

## 선행 조건

- M2 완료 (가격이 있어야 매출이 계산된다)

---

## 완료 판정

- [ ] 손님이 초밥을 먹으면 매출이 가격만큼 누적된다
- [ ] 제한 시간 내 목표 매출 도달 시 **클리어**, 미달 시 **실패** 판정이 난다
- [ ] 목표 매출·제한 시간을 `StageConfig` 에서 읽는다 (코드 상수 0)
- [ ] 클리어 후 보상 선택 화면이 뜨고, 고른 보상이 덱/손님 목록에 반영된다
- [ ] 매출·클리어 판정이 전부 EditMode 로 검증된다
- [ ] EditMode 전량 Green + `/run webgl` 유지

**시너지 (선택사항 — 위가 다 끝난 뒤)**
- [ ] 초밥이 **특성(Trait)** 을 가진다
- [ ] 특성 초밥을 처리한 손님에게 **일정 시간/횟수 동안 버프**가 걸린다 (추가 점수 / 소화 속도↑ / 먹는 속도↑ / 체감 포화도↓)
- [ ] 버프가 **배정 우선순위를 바꾸지 않는다** (예측 가능성 유지)

## 산출물

### `Runtime`

| 타입 | 책임 |
|---|---|
| 점수/매출 집계 | `SushiEatenEventChannelSO` 구독 → 가격 누적 |
| `StageController` 로직 | 제한 시간, 목표 대비 진행도, 클리어/실패 판정 |
| `RunState` | 현재 덱, 보유 손님, 진행 스테이지 |
| 보상 생성기 | 클리어 시 제시할 보상 후보 목록 |
| *(선택)* 버프 컨테이너 | 손님별 활성 버프와 잔여 시간/횟수. **순수 클래스** |
| *(선택)* 시너지 판정기 | 특성 → 버프 발동. **순수 함수** |

### `Presentation`

- 매출·남은 시간 HUD
- 보상 선택 화면 — **MVP 패턴** (`View` / `Presenter` / `Model`). `Presenter` 는 순수 C# 이라 테스트 대상 (§3.6)

---

## 작업 순서

1. **매출 집계** (`Runtime`) — 이벤트 채널 구독 → 누적. 실패 테스트 우선
2. **클리어 판정** (`Runtime`) — 시간·목표 대비 판정 전이
3. **시너지 계산** (`Runtime`) — 순수 함수. 태그 조합 테스트
4. **`RunState` + 보상 생성** (`Runtime`)
5. **HUD** (`Presentation`)
6. **보상 선택 화면** (`Presentation`, MVP) — Presenter 테스트 포함

1~4 는 순수 로직이라 병렬 여지가 크다. 5~6 은 그 뒤.

## 테스트 항목

| 대상 | 테스트 이름 예시 |
|---|---|
| 매출 누적 | `AddScore_SushiEaten_IncreasesByPrice` |
| 클리어 | `Evaluate_TargetReachedBeforeTimeout_Clears` |
| 실패 | `Evaluate_TimeoutBeforeTarget_Fails` |
| 경계 | `Evaluate_TargetReachedExactlyAtTimeout_Clears` ← **동작 정의 필요** |
| 시너지 | `Calculate_SalmonSetComplete_AppliesBonus` |
| 보상 반영 | `ApplyReward_SushiCard_AddsToDeck` |
| Presenter | 보상 선택 시 Model 갱신 (View 는 스텁) |
