## A. 카드 틀의 늘어나는 가운데를 단색으로 (P6)

### 목적

카드 설명이 배경 무늬에 겹쳐 읽기 어렵다. 원인은 «무늬» 가 아니라 **띠 하나**다.

`card_frame` 은 48×64 원본의 **캔버스 좌표 `y 50~60`** 에 어두운 띠를 깐다. 카드가 96×128 이고
수치 줄이 바닥에 있던 시절 그 줄 뒤를 받쳐 **대비를 만들던 장치**였다.

**9-slice 가 그 전제를 깼다.** 테두리가 `(8,8,8,8)` 이므로 늘어나는 구간은 **`y 8~55`** 이고,
띠의 위쪽 6줄(`50~55`)이 거기 걸린다 — 그 6픽셀이 카드 안쪽 176px 전체로 늘어나 스탯 행 뒤를
얼룩지게 만든다. 글자를 읽히게 하려고 넣은 것이 지금은 정확히 반대로 작동한다.

**그래서 할 일은 «단색으로 칠하기» 가 아니라 «띠를 걷어내기» 다.** 두 줄을 지우면 가운데는
이미 `fill` 단색이다.

## B. 포화도 칸의 배경판 `bar-slot` (P5 선행)

### 목적

포화도 칸은 손님 오른쪽 세로바로 옮겨진다(step-03). 그런데 **테이블 스프라이트가 자리 기준
좌우 ±1 유닛·아래로 −1.85 유닛을 덮어서**, 손님 옆 어디에 두든 바의 **아래쪽 절반은 테이블
위, 위쪽 절반은 벽 위**가 된다. 같은 금색 칸이 배경에 따라 다르게 읽힌다.

**위치로는 못 푼다.** 테이블을 완전히 벗어나려면 |x| > 1 이어야 하는데 그러면 손님에게서
떨어져 보이고, 자리 2·3 은 간격이 2 유닛뿐이라 이웃 테이블에 닿는다. **배경이 무엇이든 칸이
읽히게 만드는 쪽**이 자리마다 사정이 다른 것을 쫓아다니지 않는다.

### 새 스프라이트

```python
def bar_slot() -> Canvas:
    """12x12 포화도 칸 배경판. 칸(8x8)보다 사방 2px 크다."""
```

- **12×12.** 칸이 8×8 이므로 사방 2px 여유. 칸 간격(0.14 유닛)보다 배경판이 커서 **칸이 이어지면
  배경도 이어져** 한 줄기 기둥으로 보인다 — 판을 따로 한 장 깔지 않아도 된다
- 색은 **불투명**하게 한다. 반투명이면 겹치는 구간만 두 번 어두워져 줄무늬가 생긴다
- `RAIL_DARK` 바탕 + `RAIL` 안쪽 한 겹 정도가 기존 톤에 맞는다. **정확한 색은 사람이 화면에서
  정한다**
- `SPRITES` 사전에 `"bar-slot": bar_slot` 을 더한다
- **`SLICE_BORDERS` 에는 넣지 않는다.** 9-slice 가 아니다 — 원본 비율 그대로 균일 배율로 쓴다

> **9-slice 로 만들지 않는 이유가 있다.** 테두리를 주면 `.meta` 의 스프라이트 시트 항목을
> 손봐야 하는데 **에이전트는 `.meta` 를 편집할 수 없다**(RULE-03) — M6.5 에서 카드 틀의
> 테두리를 사람이 Sprite Editor 로 넣어야 했던 것과 같은 벽이다. 균일 배율로 쓰면 그 벽이
> 아예 없다.

### 이 스프라이트를 여기서 만드는 이유

step-03 은 프리팹만 만지는 단계이고, `Assets/Art/` 에 새 원본을 더하는 것은 **§9 승인
항목**이다. 승인을 한 번에 받고 PNG 커밋도 한 곳에 모은다.

## 에이전트 실행 지침

`/task-start` 를 먼저 호출해 범위를 확정한 뒤 아래를 수행한다.

### 생성/수정 파일

- `scripts/make-ui-sprites.py` — 수정 (`card_frame` 수정 · `bar_slot` 추가)
- `Assets/Art/Sprites/UI/card-frame.png` — **재생성** (원본 애셋, §9)
- `Assets/Art/Sprites/UI/card-frame-disabled.png` — **재생성** (원본 애셋, §9)
- `Assets/Art/Sprites/UI/bar-slot.png` — **신규** (원본 애셋, §9)
- `Assets/Tests/EditMode/Editor/UiSpriteAssetTests.cs` — 수정 (검사 추가 · `Expected` 항목 추가)

### 순서 (TDD)

1. **검사를 먼저 쓴다.** 지금 실행하면 **둘 다 실패해야 한다** — 단색 검사는 띠 때문에,
   `bar-slot` 크기 검사는 파일이 없어서. 실패하지 않으면 검사가 틀린 것이다 (아래 «공허 확인»)
2. 생성기에서 두 줄을 지우고 `bar_slot` 을 더한다
3. `python3 scripts/make-ui-sprites.py` 로 다시 찍는다
4. Unity 가 임포트하도록 새로고침한 뒤 테스트 전량

> `bar-slot.png` 은 신규 파일이라 임포트 후 `.meta` 가 **생성된다.** 그것은 편집이 아니라
> 생성이므로 RULE-03 위반이 아니다. 다만 **생성된 `.meta` 를 손으로 고치지는 않는다** —
> PPU·필터·압축은 `PixelArtImportSettings` 가 경로 규칙으로 자동 적용한다

### 생성기 변경 — A(카드 틀)

`card_frame` 에서 **이 두 줄만** 지운다:

```python
    # 아래쪽 수치 줄 자리를 한 단 어둡게 깔아 텍스트 대비를 만든다.
    c.rect(3, 50, 42, 11, PLATE_DARK if not disabled else RAIL_LIGHT)
    c.rect(3, 50, 42, 1, inner)
```

- **`disabled` 쪽도 같이 고쳐진다.** 두 스프라이트를 찍는 곳이 이 함수 하나다 — 의도한 것이다
- **네 모서리 못은 그대로 둔다.** `(3,3)`·`(43,3)`·`(3,59)`·`(43,59)` 는 테두리 영역(0~7) 안이라
  늘어나지 않는다. 요구가 *"side, corner 제외"* 라고 적은 것과 맞는다
- **테두리·프레임·`fill` 세 줄은 건드리지 않는다**
- 함수 docstring 에 **왜 가운데가 비었는지**를 한 줄 남긴다 — 안 적으면 다음 사람이 «허전하다»
  며 다시 채운다. 가리되 이름을 부르지 않는다
  ([`rules/scripts.md`](../../.claude/rules/scripts.md) §7)
- (선택) 모듈 상단 `SLICE_BORDERS` 에 `"card-frame": (8, 8, 8, 8)` · `"card-frame-disabled"` 를
  더한다. **출력 메모일 뿐 임포터에 물리지 않으므로** 동작에는 영향이 없고, 지금은 카드 틀만
  빠져 있어 읽는 사람이 «테두리가 없는 스프라이트» 로 오해한다

### 추가할 검사 — A (단색)

```csharp
// UiSpriteAssetTests
[Test]
public void StretchedRegion_IsFlat([ValueSource(nameof(SliceBorderNames))] string name)
```

- **늘어나는 영역만 본다.** 테두리 8 이므로 검사 범위는 텍스처 좌표 `[8, w-8) × [8, h-8)`
- 그 영역의 픽셀이 **전부 같은 색**임을 단언한다. 다르면 «어느 좌표에서 어떤 색이 나왔는지»를
  메시지에 넣는다 — 안 넣으면 실패했을 때 생성기의 어느 줄인지 못 찾는다
- **`button` · `panel` 도 같은 검사를 통과해야 한다.** 통과하지 못하면 그 스프라이트는 원래
  가운데에 무늬가 있는 것이므로, 대상 목록을 `card-frame` 둘로 좁히고 **왜 좁혔는지 주석에
  남긴다.** 목록을 좁히는 쪽이 검사를 느슨하게 고치는 것보다 낫다

**픽셀을 읽는 방법.** `AssetDatabase` 로 온 `Texture2D` 는 읽기 불가일 수 있어 `GetPixels` 가
던진다. `File.ReadAllBytes` + `ImageConversion.LoadImage` 로 **디스크의 PNG 를 임시 텍스처에
직접 올려** 읽는다. 그러면 임포트 설정과 무관하게 항상 성립하고, 무엇보다 **생성기가 찍은
그림 자체**를 보게 된다.

### 추가할 검사 — B (`bar-slot`)

- `Expected` 사전에 `["bar-slot"] = new Vector2Int(12, 12)` 를 더한다. 그러면
  **크기·임포트 설정·«테두리 0»** 세 검사가 자동으로 따라붙는다(`FixedNames` 가
  `SliceBorders` 에 없는 이름을 전부 가져간다) — 새 테스트를 손으로 쓸 것이 없다
- **칸(8×8)보다 커야 한다**는 관계를 한 줄로 박는다. 숫자를 두 곳에 적어 두면 한쪽만 바뀌는데,
  이 둘은 «배경이 칸을 덮는다» 라는 **관계**가 요구사항이다:

```csharp
[Test] public void BarSlot_IsLargerThanTheCell()   // bar-slot > bar-cell, 두 축 모두
```

### 공허 확인 (필수 — [`rules/tests.md`](../../.claude/rules/tests.md) §3)

`git stash` 로 생성기 수정을 되돌리고 **옛 PNG 로 새 검사만 돌린다.** 실패해야 한다.
전량 통과하면 세 원인을 순서대로 배제한다:

1. **검사가 헛돌았나** — 경로·범위가 맞나. 테두리를 빼는 좌표 계산이 뒤집혀 테두리만 보고 있을
   수 있다
2. **주입이 관측 범위 밖인가** — 띠는 캔버스 좌표 `y 50~55` 에 있고, `LoadImage` 로 올린
   텍스처는 **y 가 아래에서 위로** 간다. 두 좌표계를 섞으면 엉뚱한 줄을 본다
3. 그때 비로소 검사를 고친다

### 밸런스 수치

없다. 색은 팔레트 상수이고 새 수치를 만들지 않는다.

### 제약

- **RULE-03 — `.meta` 를 편집하지 않는다.** 크기가 48×64 로 같으므로 스프라이트 시트 항목과
  9-slice 테두리는 그대로 남아야 한다. **남았는지 확인**은
  `StretchedSprites_HaveNineSliceBorders` 가 이미 한다 — 그 테스트가 깨지면 재생성이 `.meta` 를
  건드렸다는 신호이므로 **되돌리고 보고**한다
- **RULE-02(워크트리)** — `Assets/Art/` 가 심링크인 환경이라면 워크트리 git 이 새 파일을 못 본다.
  주 저장소에서는 실제 폴더라 해당 없음. 확인: `ls -la Assets/ | grep Art`
- **§9 — 원본 애셋 커밋은 사람 승인이다.** 세 PNG(재생성 2 · 신규 1)를 스테이징하기 전에
  **최종/공개용이 맞는지 확인받는다.** `preflight.sh` 의 에셋 유출 검사가 `warn` 으로 잡을
  것이며, 그것을 지나치지 않는다
- **`.png` 를 손으로 칠하지 않는다** (README D9)
- **네 화면이 함께 바뀐다** — 손패·덱 보기·보상·백과사전이 한 틀을 쓴다 (M6 D3)
- **`bar-cell` 을 건드리지 않는다.** 배경판은 별도 스프라이트다 — 칸에 테두리를 그려 넣으면
  `SaturationBarView` 가 칸 전체를 틴트하므로 **테두리까지 같이 물든다**

## 금지 사항

- 카드 틀의 **색·테두리·모서리 못**을 바꾸지 않는다. 이번에 지우는 것은 띠 하나다
- `Card.prefab` · `Customer.prefab` 을 건드리지 않는다 — step-02 · step-03 의 몫이다
- `bar-slot` 에 9-slice 테두리를 붙이지 않는다 (`.meta` 를 만져야 한다 — RULE-03)
- 테스트가 깨졌을 때 `[Ignore]` 로 덮거나 검사 범위를 넓히지 않는다. 원인을 보고한다
