# 화면과 소리 (M5)

로직이 이미 내고 있는 사실을 **보이게·들리게** 옮기는 계층. 이 계층은 판정하지 않는다.

## 1. 그림은 데이터가 정한다

`SushiData.Icon` · `CustomerData.Icon` → 뷰가 `Bind` 시점에 한 번 대입한다.

- **종류나 가격으로 코드에서 분기하지 않는다.** 그러면 초밥을 추가할 때마다 뷰를 고쳐야 한다
- **아이콘이 비면 프리팹의 그림을 그대로 둔다.** 빈 화면을 만들지 않는다 — 아이콘을 아직 안
  채운 애셋에서 초밥이 사라지면 벨트가 고장 난 것처럼 보인다
- 풀에서 **반납할 때 그림을 되돌린다.** 남겨 두면 재사용 첫 프레임에 직전 초밥이 번쩍인다

구분 축이 둘이다 — **접시 테두리 = 가격 티어**, **네타 색 = 종류**. 손님은 **실루엣**으로만
구분한다. 색은 `CustomerView` 가 상태 틴트(Idle/Eating/Digesting/대기)로 이미 쓰고 있어서,
유형까지 색에 태우면 두 정보가 같은 채널에서 싸운다.

> **티어 색을 고를 때 네타 팔레트를 함께 본다.** 3티어 접시를 `#D94A5A` 로 잡았다가 참치
> 네타 `#D63B57` 과 거의 같아 구분이 안 됐다. 둘은 같은 스프라이트 안에서 경쟁한다.

## 2. 소리는 3층이다

| 층 | 사는 곳 | 하는 일 |
|---|---|---|
| **값** | `AudioBankSO` (`Runtime.Data`) | 클립·볼륨·간격·동시 재생 상한 |
| **판정** | `SoundBudget` · `AudioUnlockGate` (`Runtime`) | 지금 내도 되나 |
| **재생** | `AudioDirector` (`Presentation`) | 사건 구독 → `PlayOneShot` |

간격·상한이 SO 에 있는 이유: 겹침이 거슬리는지는 **플레이하며 조정하는 값**이다. 판정이
`Runtime` 에 있는 이유: `AudioSource` 없이 "0.05초 안에 셋" 을 EditMode 로 재현해야 한다.

**예산과 게이트를 합치지 않는다.** 예산은 *너무 많다·너무 잦다*, 게이트는 *아직 아무것도
안 된다* 를 본다 — 합치면 "소리가 안 났다" 의 원인이 둘 중 어느 쪽인지 테스트에서 구분되지
않는다.

### 자동재생 정책 — 씬 시작에 배경음을 재생하면 안 된다

브라우저는 사용자 제스처 전까지 오디오를 잠근다. **그 상태에서 낸 소리는 밀리지 않고
사라진다.** 잠금은 첫 손님 배치(=클릭)로 푼다.

> **`AudioSource.playOnAwake` 는 기본값이 켜져 있다.** 그대로 두면 씬이 열리자마자 잠긴 채로
> 재생이 시작되고 브라우저가 그것을 버려서, 게이트를 만든 이유 자체가 무력화된다.
> `AudioDirector` 가 `Awake` 와 `Bind` 양쪽에서 끈다 — 단, **이미 열린 뒤에는 멈추지 않는다.**
> `Bind` 는 스테이지마다 불리는데 거기서 멈추면 판이 바뀔 때마다 배경음이 끊긴다.

### 배경음은 뱅크에 두 칸 (M7)

화면마다 다른 것은 **배경음 하나뿐**이라, 뱅크를 둘로 쪼개는 대신 칸을 하나 늘렸다
(`Bgm` / `MainBgm`). 쪼갰다면 효과음 볼륨·간격이 두 곳으로 갈라져 한쪽만 고치는 사고가
난다.

어느 칸을 틀지는 씬이 정한다 — `AudioDirector._bgmTrack` (`BgmTrack.Stage` / `.Main`).
**씬에 있는 유일한 오디오 설정이며**, 곡과 볼륨은 그대로 애셋에 남는다.

> `Main.unity` 의 `AudioDirector` 는 오랫동안 `_bgmSource` 가 비어 있었다. 그 상태에서는
> `StartBgm` 이 조용히 돌아 나가 **메인 화면에 아무 음악도 없다** — 예외도 로그도 없다.
> `MainSceneTests.MainScene_PlaysItsOwnBgm` 이 그 둘(소스 없음 / 곡 잘못 고름)을 함께 막는다.

### 잠금은 페이지 단위다 — 씬 단위가 아니다 (M7)

브라우저가 한 번 연 것은 다시 잠기지 않으므로, 잠금 상태도 씬을 넘어 이어져야 한다.
게이트를 인스턴스마다 들고 있었을 때는 씬이 바뀔 때마다 새 진행자가 **잠긴 채로 태어나**,
메인 → 스테이지 → 메인 어느 쪽으로 가도 다시 클릭하기 전까지 음악이 없었다.

- 잠금은 `static`, 되돌리기는 `SubsystemRegistration` (RULE-01)
- **「열린 순간」은 인스턴스마다다.** 잠금만 이어받으면 다음 화면이 자기 배경음을 못 켠다 —
  이미 열린 페이지에서 태어난 게이트는 순간을 하나 들고 시작하고, `AudioDirector.Start` 가
  그것을 소비한다
- **버튼만이 제스처가 아니다.** 잠금을 푸는 길이 버튼과 배치 둘뿐이라 제목 화면의 빈 곳은
  아무리 눌러도 소용이 없었다. 지금은 아무 입력이나 받는다 — 다만 **완전한 자동 재생은
  불가능하다**

### 볼륨은 세 층이다 (M7)

큐별(`AudioBankSO`) × 갈래별(`VolumeMix`) × 마스터(`AudioListener.volume`).

가운데 층만 우리가 드는 이유: 엔진에 갈래별 볼륨을 둘 곳이 없다. 설정은 메인 화면에만
살고 소리를 내는 진행자는 씬마다 새로 태어나므로, 인스턴스로 들면 스테이지로 넘어가는
순간 잃는다 — `AudioListener.volume` 이 전역인 것과 같은 이유로 전역이다.

> **`AudioMixer` 를 쓰지 않았다.** 정석이지만 그룹과 노출 파라미터를 스크립트로 만들 길이
> 없어 애셋을 손으로 짜야 하고, 그러면 값이 코드에서 사라져 EditMode 로 확인할 수 없다.
> 갈래가 둘뿐인 동안은 이쪽이 싸다.

**지금 울리는 곡에도 반영해야 한다.** 시작할 때만 곱하면 슬라이더를 움직여도 다음 곡부터
적용되어, 플레이어에게는 설정이 고장 난 것으로 보인다.

### 클립을 갈아 끼울 때는 참조가 끊긴다

`.wav` 를 같은 이름의 `.mp3` 로 바꿔 넣으면 **GUID 가 새로 발급된다.** 뱅크는 GUID 로
클립을 물고 있으므로 넷이 통째로 끊겼고, 게임은 그냥 조용해졌다. 끊긴 참조는 `null` 로
역직렬화되어 예외도 로그도 남기지 않는다.

`AudioBankAssetTests.EveryCue_HasClip` 이 유일한 그물이다. 큐를 늘리면 그 목록도 늘린다.

## 3. 연출 수치와 밸런스 수치의 구분선

*"사람이 밸런싱하며 만질 값인가"* 하나로 가른다.

| | 어디에 | 예 |
|---|---|---|
| 밸런스 | SO | 간격 · 볼륨 · 동시 재생 상한 |
| 연출 | 프리팹의 `[SerializeField]` | 이펙트 수명 · 크기 · 색, 클릭 반경 |
| 파이프라인 | 코드 상수 **한 곳** | PPU · 필터 모드 · 압축 |

연출 수치를 SO 로 빼면 애셋만 늘고 찾기 어려워진다 — 그 프리팹 하나에만 의미가 있다.

## 4. 임포트 설정은 코드가 강제한다

`Editor/Import/` 에 텍스처·오디오 두 규칙이 있다. 사람 손에 맡기면 반드시 샌다.

| | 대상 | 강제하는 것 |
|---|---|---|
| `PixelArtImportSettings` | `Assets/Art/Sprites/` · `Assets/Art/Animations/` · `Assets/Level/Placeholder/` | Point · 밉맵 끔 · 무압축 · PPU 32 · FullRect (+ **시트만** 32×32 로 자르기) |
| `AudioImportSettings` | `Assets/Audio/Music/` · `Assets/Audio/Sound/` | Music=CompressedInMemory / Sound=DecompressOnLoad, Vorbis, Preload |

- **`Assets/Art/Fonts/` 는 대상 밖이다.** 폰트 아틀라스가 픽셀 규칙에 걸리면 TMP 폰트가 깨진다
- **경로 판정은 끝 슬래시를 포함한 `StartsWith` 다.** `Contains` 는 패키지 경로를 오탐한다
- 두 규칙에 **공통 추상을 만들지 않았다** — 세 번째 사례가 나오면 그때 뽑는다 (R4)
- 텍스처 규칙은 최대 해상도를 **강제하지 않는다.** 배경이 정당하게 클 수 있고, 캡은 사람이
  의도한 해상도를 조용히 반토막 낸다
- **자르기 모드는 시트에만 쓴다.** 낱장까지 못박으면 사람이 스프라이트 에디터에서 나눠 둔
  것을 매번 되돌린다 → [`stage-scenery.md`](stage-scenery.md) §5

## 5. 한글은 정적 서브셋으로 굽는다

**WebGL 은 OS 폰트에 접근할 수 없다.** 폰트에 없는 글자는 두부(□)가 되고, 에디터에서는
시스템 폰트가 메워 주므로 **빌드해야만 드러난다.**

- 글자 목록은 손으로 관리하지 않는다 → [`scripts/extract-charset.py`](../../scripts/extract-charset.py)
- **주석은 담지 않는다.** 이 프로젝트는 문서 주석이 두꺼워, 담으면 한글 489자 / 리터럴만 담으면
  89자다 — 아틀라스 한 단계(512↔1024)를 가른다
- **픽셀 폰트는 SDF 로 굽지 않는다.** 모서리가 둥글려져 픽셀이 죽는다. Render Mode 는 `RASTER`,
  Sampling Point Size 는 폰트 네이티브 높이의 정수배
- `KoreanFontCoverageTests` 가 두부 회귀를 잡는다. 문구를 바꾸면 **깨져야 정상인 테스트**다

## 6. 입력은 Input System 이다

`ENABLE_LEGACY_INPUT_MANAGER` 가 **정의되어 있지 않다.** `UnityEngine.Input` 은 런타임에 예외를
던진다.

> M5 에서 이 사실을 확인하기 전까지 `StageTransitionView` 의 Enter 와
> `RewardSelectionView` 의 Esc·숫자키가 **동작하지 않았다** — 데모가 스테이지 1 을 넘어갈 수
> 없는 상태였다. 두 뷰의 `Update` 는 화면이 열려 있을 때만 입력을 읽는데 PlayMode 테스트가
> 화면을 열지 않아, **코드도 테스트도 멀쩡한데 재생만 죽는** 형태였다.
>
> `InputBackendTests` 가 전제를 컴파일 시점에 고정한다.

**자리 선택은 물리를 쓰지 않는다.** 자리는 넷뿐이고 좌표가 알려져 있어 `SlotPicker` 의 거리
비교로 끝난다 — 콜라이더는 씬에 관리할 것을 늘리고, 물리 질의는 호출 시점 제약이 붙는다
(RULE-04).

## 7. 씬 조립에서 반복해 걸린 것

- **`ResolveMissingReferences` 는 자기 필드만 챙긴다.** 컴포넌트가 들고 있는 자기 참조는
  씬의 몫이다 — `EffectDirector._pool` 이 비어 오디오는 나는데 이펙트만 안 뜬 적이 있다.
  형제를 **이름으로** 찾게 해서 해결했다 (타입으로 찾으면 초밥 풀과 구분되지 않는다)
- **`Initialize(..., null, ...)` 가 `Awake` 가 잡아 둔 참조를 지운다.** 씬 진입점이 카메라를
  들고 있지 않아 `null` 을 넘기는데 그대로 대입하면 클릭이 통째로 죽는다. 넘어온 값이 없으면
  덮지 않는다
- **씬 인스턴스가 프리팹 크기를 오버라이드로 붙든다.** 카드 틀을 128×192 로 키워도 씬의
  카드만 옛 크기로 남아, **라벨은 새 배치인데 틀만 작아 글자가 잘린다.** M6.5 에서
  `Stage01`·`Main` 두 씬을 각각 손으로 고쳤고, 보고 있는 것이 없어 **같은 실수를 두 번**
  했다 — 지금은 씬 테스트가 프리팹과 대조한다. 「틀은 하나」(M6 D3)는 프리팹 이야기이지
  씬 인스턴스까지 저절로 따라오지 않는다
- **Build Settings 에 씬을 등록하지 않으면 빈 씬이 빌드된다.** 빌드는 성공하고 엔진도 예외
  없이 뜨는데 화면에는 카메라 클리어 색만 나온다. `EditorBuildSettings.asset` 은
  `scripts/run.sh` 의 공유 애셋 보호가 빌드 후 되돌리므로 **커밋해 두어야** 남는다

## 8. WebGL 실측 (M8 기준선)

무압축, 두 시점:

| | `074392f` (M5) | `7dc0744` (M6) | `ab77dba` (M6.5) |
|---|---|---|---|
| `.wasm` | 29.78 MB | 29.84 MB | 29.84 MB |
| `.data` | 12.65 MB | 12.84 MB | 12.84 MB |
| `.js` | 0.33 MB | 0.33 MB | 0.31 MB |
| **초기 로드** | **42.45 MB** | **43.00 MB** | **42.99 MB** |

M6 은 씬 하나(`Main.unity`)와 UI 스프라이트 11장, 한글 폰트 재굽기를 더했는데 **증가분이
0.55 MB 로 거의 `.data` 쪽**이다. 코드가 늘어도 `.wasm` 은 사실상 제자리 — 이 프로젝트에서
빌드 크기를 좌우하는 것은 스크립트가 아니라 애셋이다.

**M6.5 는 그 결론을 한 번 더 확인했다.** 클래스 넷·씬 오브젝트 여덟을 더했는데 크기가
**제자리**다(−0.01 MB). 새 애셋이 0 이었기 때문이며, 반대로 말하면 스프라이트 한 장이
스크립트 수천 줄보다 크다.

`webGLCompressionFormat` 은 Brotli 인데 산출물에 `.br` 이 없다 — 서버 압축을 전제한 설정으로
보이며, wasm 은 보통 4~5배 압축된다. `stripEngineCode` 는 켜져 있다.

**`Assets/TextMesh Pro/Resources/` 2.2MB 가 통째로 빌드에 실린다** (Resources 폴더는 참조 여부와
무관). 대부분이 `LiberationSans SDF` 기본 폰트이고 우리 화면에는 안 나오지만, TMP 가 폰트 없을
때 이것으로 폴백하므로 함부로 지우면 안 된다. **M8 에서 판단할 항목이다.**

브라우저에서 확인한 것: 한글 두부 **0**, 예외 **0**, HUD 레이아웃 정상, 클릭 배치 동작,
접시 티어 색 구분. 확인하지 못한 것은 §9.

## 9. 아직 확인하지 못한 것

- **먹힘 → 소리·이펙트의 실제 관측.** 자동화 브라우저에서는 캔버스가 포커스를 못 받아 Unity 가
  심하게 스로틀한다(5초에 게임 1초). 배선은 `Play_Scene_EatenSushi_ReachesAudioAndEffects` 가
  덮지만 **귀로 듣는 확인은 사람이 해야 한다**
- **드래그로 손님 앉히기.** M6 에서도 못 봤다. 브라우저 패널이 **숨겨지면 `requestAnimationFrame`
  이 사실상 멈춘다** — 스크린샷은 강제 페인트라 그림이 나오지만 게임 시간은 흐르지 않는다
  (스테이지 시계가 60 에서 움직이지 않는 것으로 드러난다). uGUI 드래그는 여러 프레임에 걸쳐야
  성립해서 합성이 끝까지 가지 않는다. **«스크린샷이 나온다» 를 «게임이 돈다» 로 읽지 않는다**
